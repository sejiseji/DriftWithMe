# Codexへ渡す開始指示

## 貼り付け用プロンプト

```text
このフォルダのSPEC.md、TASKS.md、ACCEPTANCE.md、data/*.jsonを読み、
メンダコのジャックと電子化人類のヒューズを想定したPyxel試作を実装してください。

今回はJWP000〜JWP002を実装し、E0で止めて報告してください。
環境調査だけで終えず、正方形マップで立方体を歩かせる起動物と、
モバイル用の入力・Web表示・簡易SEの土台まで進めてください。

重要な方針：
・初期地面は32×32セル、1セル32、1024×1024の平坦な正方形です。
・まず自キャラは立方体。完成メンダコ絵を作る必要はありません。
・画面は横持ち、仮512×236。426×196と640×294も設定として残します。
・カメラは浅い俯瞰の半固定。ユーザー操作の自由パン・回転・ピンチは不要です。
・ドラッグ移動と、その場の長押しバリアを入力所有権で区別してください。
・後続の通常ウニ／泡捕獲／ヒューズの電撃を見据えますが、今回のウェーブでは
  それらを全部実装しないでください。
・SEは最初から用意しますが、試聴と実ゲームの成功イベントを区別してください。
・既存Riversideを改変する場合は独立モードを作り、既存の動作・テストを守ってください。
・過去のコミット番号やローカル絶対パスを現在の実装と推定しないでください。

まず作業フォルダのAGENTS/README、git status、Python/Pyxel版、
既存の入力・投影・Web起動経路を確認してください。
空の新規フォルダなら最小プロジェクトを作ってください。
未コミット作業を勝手に削除・上書きしないでください。

データを取り込むパスは実装構成に合わせて構いませんが、
ゲームが読むファイルと文書に記した値が乖離しないようにしてください。
根拠のない架空APIを使わず、採用するPyxelのAPIとWebランタイムを確認し、版を固定してください。

各ウェーブでコード・テスト・起動確認を進めてください。
iPhone実機を操作できない場合は、Web成果物と手動試験手順を用意し、
実機確認はNOT_RUNとして報告してください。
未確認の性能や音声出力を確認済みと書かないでください。

許可のないpush・公開・履歴書き換えはしないでください。
最後に、実装内容、検証結果、未確認項目、実行コマンド、差分状態、
次に実装するJWP003の内容を報告してください。
```

## パックの置き方

このフォルダは仕様・初期データのパックで、ゲームのソースコードではありません。新規プロジェクトなら `docs/prototype_spec/` 等へ配置できます。すでにAGENTS.mdがある場合は置換せず、その指示を読んだ上でこの仕様を参照させてください。

SPECだけでなくdataとACCEPTANCEも渡してください。設定の単位、攻撃の成立条件、モバイルの入力排他などが実装のずれを防ぐ部分です。

次のウェーブへ進めるときは、前回の実装報告と現在のテスト結果を読ませ、TASKSの該当IDを指定します。すべてのウェーブを一括生成することを初回の前提にしないでください。
