# 月・週を選ぶテスト用メニュー

通常起動でも窓口右上のカレンダーから月・週の選択画面を開ける。
6月・7月・8月の各第1〜4週（12週）を選び「移動」をタップする。
開く・月週を選ぶ・閉じるだけでは進行や保存方式を変更しない。
「移動」で既存の週開始初期化を呼び、通常保存から一時テストセッションへ切り替える。
会話中も利用できる。週・外勤遷移中はカレンダーを表示しない。
外勤中は「週選択・保存なし」で選び直せる。

Web版は `?debug=weeks`（既存クエリがあれば `&debug=weeks`）、
Mac版は `python main.py --week-debug` でも従来のテストメニューへ入れる。
従来メニューには他のプレビューと「通常プレイへ戻る」がある。
窓口の簡潔な選択画面には月・週・移動・閉じるだけを表示する。
窓口版から通常プレイへ戻るには再読込する。

移動後の通常進行ストアはメモリ専用。明示的な保存成功を必要とする8月の目撃・
報告なども、状態を検証してメモリへ保存したときだけ成功する。
デバッグ入口の週だけ、それ以前の週履歴がないことを許容する。
通常セーブの読込・書込は従来どおり完了済みの前週履歴を必須とし、この例外を使わない。
通常の自動チェックポイントはデバッグ中の二重ガードを維持する。
本番の通常セーブ・バックアップ・花壇専用配置保存は読み書きしない。
通常保存へ戻るときにだけ通常の保存を読み直す。

花壇の配置・会話カーソルも専用のメモリ領域を使用する。本番配置は取り込まない。
同じデバッグセッション内の再ジャンプでは一時配置を引き継ぐ。
進行ストアは再ジャンプで消去し、新しい週の最初から始める。
再読込・通常復帰では進行と一時配置を破棄し、本番へ転記しない。
開閉・キャンセルだけでは進行・一時保存を破棄しない。

週開始時は会話・戦闘・外勤・遷移などを初期化し、対象週に必要な前提だけを設定する。
8月第4週では既存の巡回配置を使用する。最終報告後の未執筆の休暇・エンディングや
8月第4週より先へ進む機能は追加しない。

対象週のUI・案件検証ではこのメニューで前工程をスキップしてよい。
週遷移や前提条件の回帰検証は通常の順番で進める経路も残す。
検証結果には「デバッグ経由」または「通常経路」を記載し、両者を区別する。
保存安全性は個人の保存を使わず、専用ブラウザプロファイルと合成セーブで検証する。
