# 群れ戦：本編接続テスト

本編のフィールド・移動・遭遇・戦闘・復帰・保存へ接続済み。通常起動では群れ戦を無効にして既存の戦闘と進行を保持する。混成6体だけを対象とし、物語・窓口イベント・自動週送りは追加していない。

## 本編で試す

Pyxel 2.9.9 を導入済みのリポジトリのルートで:

```sh
python main.py --swarm-field
```

タイトルまたは窓口で **F5** を押すと実際の本編マップへ入る。通常の窓口から外勤へ入った場合も、フラグが有効なら同じ3地点で遭遇する。F5は物語を進めずフィールドへ入る開発用導線。

- 北西 `(200,800)`、北東 `(800,800)`、南東 `(800,200)` の地点に36以内まで近づくと群れ戦。F6/F7/F8で実プレイヤーを各地点へ移す開発用近道も使用できる。
- 敵は左右の外周楕円上に3体ずつ配置。左右中央の敵が最も外側で、上・下の敵とともに包囲する。バーの共通進行率で接近する。
- 通常のGUARDボタンまたはSPACE/Xで全体捕縛を入力。捕縛後はノックバックしながら泡ごと浮遊する。トドメのタイミング入力はなく、個別戦闘のZAP待機時間（1.35秒）の後に自動攻撃する。ZAPを押すと開始を予約できるが、個別戦闘と同じ電撃チャンスの表示時間（0.85秒）は省略しない。成功後、ウニへ電撃→青サークル→収束水流→ウミウシへ水槍を追加入力なしで再生する。
- ESCで一時停止。戦闘中は移動・通常行動・会話・週イベントを停止。復帰後は入力のリリースを待ち、同じ押下がフィールド行動へ漏れない。
- 勝利は現地点の実フィールドへ戻り、その地点をクリア。撤退はフェード後に実マップ初期位置 `(160,160)` へ戻る。どちらも水・電力を持ち越し、回復なし。
- クリア地点は再接触しても再戦しない。未クリア地点は2秒の再接触待ちと、いったん地点から離れる条件を満たすと再戦できる。新しい戦闘はフジ援護が1回に戻る。
- 週ごとの3地点クリアで「その週の戦闘完了」を記録する。既存週の物語・報告・週送りへは未接続。単種編成、7〜8体編成、正式な出現位置調整も今後の対象。

## 資源・保存

`src/drift_with_me/data/swarm_config.json` に試作値を分離。捕縛水と電撃電力が `null` の場合は、既存設定 `bubble_water_cost`（12）/ `discharge_energy_cost`（20）を使用。混成トドメの水槍は仮に水12。

成功入力時に混成トドメの水・電力を両方検査してから一括消費する安全な仮仕様。両方不足時は電力不足台詞優先。不足なら一体も撃退せず撤退。失敗自体は無消費で、成功済み捕縛を返金・再課金しない。フジ援護は捕縛失敗だけを対象とし、旧トドメ判定は廃止。演出時間や成功範囲も引き続き仮値。

既存チェックポイントに任意の `swarm` 項目（週→クリア地点のリスト）だけを追加する。旧セーブは空の進行として読める。週ごとの完了地点は撤退・再起動で保持する。戦闘途中の保存は既存方式に合わせて禁止し、実フィールド復帰後に資源と進行を保存する。途中終了した戦闘は直前のチェックポイントへ戻る。

本編をフラグ付きで手動プレイした場合は既存セーブに記録される。自動描画検証スクリプトは常にセーブ無効で実行する。

## 単独プレビュー・自動検証

単独プレビューは本編用状態機械を共有するが、簡易表示を残す。正式スプライトとフィールド背景の受入確認には、下記の本編描画検証スクリプトを使う。

```sh
PYTHONPATH=.:src python -m experiments.swarm.preview
```

SPACE/クリックで入力。1〜5は通常・捕縛水不足・混成トドメ水不足・電力不足・両方不足。Rは勝利/撤退後の再戦。単独プレビューは永続化しない。

本編の実描画と入力経路を自動確認し、PNG・GIF・最終JSONを保存する:

```sh
PYTHONPATH=src python scripts/capture_swarm_field.py --scenario success --output /tmp/swarm-success
```

7シナリオ: `success`（正常撃破）、`retry`（初回失敗→援護→成功）、`retreat`（2回失敗→撤退）、`capture-water`、`finish-water`、`energy`、`both`。

Macロック中のため物理キーボード・マウスやモバイル実機の手動確認は未実施。正式アートへの置換、音の確認、正式な物語接続、8体/単種の攻撃設計は対象外。

## 正式アセットの描画

本編群れ戦は `swarm_render.SwarmScene` から通常の `Renderer.draw_scene` を呼び、通常の背景、奥行き順、足元アンカー、リソースパネルと会話UIを再利用する。ジャック・ヒューズ・ウニは `jack_sprite.pyxres`、フジは `Fuji_32_normal.hex`、ウミウシは `electric_nudibranch/sprites.json` の正式8方向4コマを使用する。既存の泡噴射・包み込み・ホーミング電撃・消滅描画を利用し、水槍だけ新規Pyxel効果を追加する。必要な正式アセット不足はエラーにし、図形キャラに置き換えない。

戦闘で手前の木や草に隠れる場合は、同じ本編オブジェクトを一時的に徐々に透過し、勝利演出の終わりまでに元へ戻す。実プレイヤー・ヒューズのワールド位置は移動させず、カメラは個別戦闘の共通ズーム・復帰処理で遷移する。撤退時だけ黒フェードを挟んで南西初期位置へ戻り、実マップをフェードインする。

## 個別戦闘との共通処理

ズームは `combat_camera_for_session` と個別戦闘の動的ズーム倍率・復帰処理、カウントダウンとバーは `draw_combat_timing_bar` / `draw_combat_countdown_cue` を共用する。群れの捕縛は1回の入力を維持するためマーカーは1つ。バーの表示位置・速度・判定幅は個別戦闘の通常敵設定を利用する。GUARD/ZAPボタンの描画とヒット領域、キーボード・タッチ判定は既存の操作処理を呼ぶ。背景タップを攻撃入力へ変換しない。トドメはバーを表示せず、既存 `combat_zap_chance_started` イベントから実カットインを再生する。

個別戦闘との実描画比較は `scripts/capture_swarm_field.py --individual --output /tmp/individual`。群れの画面ボタン検証は `--touch`、待機中の連打検証は `--spam-wait` を付ける。
